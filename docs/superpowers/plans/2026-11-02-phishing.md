# Local phishing end-to-end implementation plan

**Goal:** Extend the existing Detect-to-Build local flow with a credential-phishing scenario, preserving suspicious login and independent approvals.

**Architecture:** Go validates a bounded JSON snapshot and correlates four observations bound to the same message, user, device and IP. Existing durable ingestion, finding admission, typed Python gRPC, Go QA and mock SOAR review deliver the investigation. Existing sandbox session revocation and outcome-derived Skills/Memory lifecycle provide response and feedback; no email provider or model is activated.

**Tech stack:** Existing Go/PostgreSQL/sqlc/Redis, Python gRPC and React/Chakra.

**Scope decisions:** Four events (`email.delivered`, `email.authentication_failed`, `email.link_clicked`, `email.credential_submitted`) in order within five minutes. Require an opaque message reference on phishing observations; reject mixing scenarios and preserve legacy hashes by omitting absent message references. Observations are claims from synthetic evidence, not proof of compromise. No email bodies, URLs, attachments, secrets or automatic closure. Mock verdict remains INCONCLUSIVE with explicit missing evidence. Response is simulated session revocation after independent proposer/approver/executor handoff, not mailbox quarantine.
